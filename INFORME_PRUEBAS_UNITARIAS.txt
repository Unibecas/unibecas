2. LO BUENO
-------------------------------------------------------------------------------

  Backend
  -------
  [+] Arquitectura ordenada por capas: rutas -> controladores -> modelos. Cada
      archivo tiene una responsabilidad clara y es fácil de seguir.

  [+] Seguro contra inyección SQL. Todas las consultas usan parámetros ($1,
      $2...). La prueba envió "medica'; DROP TABLE becas;--" y el texto viajó
      como dato, nunca como parte del SQL.

  [+] Validación de datos con Zod. Rechaza nombres vacíos o solo con espacios,
      URLs inválidas, números enviados como texto y valores fuera de los
      catálogos (modalidad y estado coinciden con las restricciones CHECK de
      la base de datos).

  [+] La actualización parcial (PATCH) es segura. Solo permite columnas de una
      lista blanca (MAPA_COLUMNAS_BECAS), arma el UPDATE con los campos
      enviados y bloquea el cambio de proveedor o universidad.

  [+] Los IDs se validan antes de consultar la base de datos: se rechazan
      cero, negativos, decimales, texto y valores mayores al límite de un
      integer de PostgreSQL (2.147.483.647).

  [+] Manejo de errores coherente: 400 por validación, 404 cuando no existe,
      500 cuando falla el servidor. El 500 no expone detalles internos y el
      error de llave foránea (23503) se traduce en un mensaje claro.

  [+] Middleware que exige Content-Type JSON en POST, PUT y PATCH (responde
      415), respuesta 404 en JSON para rutas inexistentes y cabecera
      x-powered-by desactivada.

  [+] Base de datos bien diseñada: restricciones CHECK, llaves foráneas con
      ON DELETE RESTRICT, NIT único y búsqueda sin tildes (extensión
      unaccent).

  Frontend
  --------
  [+] Hook reutilizable useFetch que centraliza las peticiones y el estado de
      carga, y que guarda el error cuando falla la red.

  [+] Componentes bien separados (Header, Hero, BecaCard, BecaDetails,
      Footer) y skeletons de carga mientras llegan los datos.

  [+] BecaCard y BecaDetails muestran correctamente nombre, universidad,
      modalidad, estado y descripción cuando reciben los datos esperados.

  [+] Rutas claras con react-router-dom (/ y /beca/:id).


-------------------------------------------------------------------------------
3. LO MALO (ordenado por gravedad)
-------------------------------------------------------------------------------

  CRÍTICO - impide usar la aplicación
  -----------------------------------
  [-] 1. Las rutas /universidades y /entidades responden siempre 500.
         Los controladores UniversidadesControl y EntidadesControl están
         vacíos, y las rutas pasan la clase completa en vez de un método. Error
         exacto: "Class constructor UniversidadesControl cannot be invoked
         without 'new'". Archivos: backend/rutas/universidades.js,
         backend/rutas/entidades.js y sus controladores y modelos.

  [-] 2. La página de inicio se queda en blanco si la API no devuelve una
         lista. HomeLayout.jsx (línea 308) hace data?.map(...). Si la API
         responde un objeto como {"error":"Not found"}, React lanza "data?.map
         is not a function" y desmonta toda la página. Este es el error que
         hace que la página "abra y se cierre".
         Lo mismo pasa en Header.jsx (línea 240) con data.slice(...) al abrir
         el menú Becas.

  [-] 3. useFetch no revisa si la respuesta fue exitosa (response.ok). Una
         respuesta 404 o 500 se guarda como si fueran datos, y "error" queda
         en null. Esto provoca el punto 2.

  [-] 4. La API responde 404 {"info": "No hay becas disponibles"} cuando no
         hay becas, en vez de 200 con una lista vacía []. Junto con el punto
         2, una base de datos vacía basta para dejar el frontend en blanco.

  [-] 5. La dirección de la API está escrita directamente en 3 archivos
         (HomeLayout.jsx, Header.jsx y BecaDetails.jsx) apuntando a
         https://unibecas.onrender.com. No se puede usar un backend local sin
         editar el código, y en la fecha de la prueba esa API respondía
         "Not found" en /main.

  MEDIO - funciona, pero mal
  --------------------------
  [-] 6. Las tarjetas de becas del inicio no muestran la descripción.
         HomeLayout pasa info.descripcion_informacion, pero la API devuelve el
         campo con el nombre "descripcion".

  [-] 7. El archivo backend/modelos/main.js (versión antigua con JSON) no se
         puede importar: pide validarUsuario y actualizarDato a esquemas.js,
         que ya no existen (SyntaxError). Es código muerto; además
         readFile/writeFile usan la ruta relativa 'datosprueba.json', que
         depende de la carpeta desde donde se arranque el servidor.

  [-] 8. Cuando CORS rechaza un origen desconocido, el servidor responde 500
         con una página HTML que incluye la traza del error (rutas internas de
         node_modules). Debería responder 403 sin detalles.

  [-] 9. Pedir una beca con un ID mal formado (/main/abc) responde 404 "no
         encontrada" en vez de 400 "ID inválido". El cliente no puede
         distinguir un ID mal escrito de una beca que no existe.

  [-] 10. El esquema de becas acepta descripción, requisitos y cobertura
          vacíos (""). La base de datos solo exige que no sean NULL, así que
          pueden guardarse becas sin información.

  [-] 11. Inconsistencia de nombres: el frontend usa la modalidad
          "Tecnológica" (con tilde) en data.js, pero el backend y la base de
          datos solo aceptan "Tecnologica" (sin tilde).

  BAJO - detalles a pulir
  -----------------------
  [-] 12. La búsqueda no escapa los comodines de LIKE. Buscar "%%%%" pasa la
          validación de 4 caracteres y devuelve todas las becas; "_" funciona
          como comodín.

  [-] 13. validarIdEntero acepta formatos raros porque usa Number(): "1e3" se
          convierte en 1000, "0x10" en 16 y " 7 " en 7.

  [-] 14. No hay pruebas en el repositorio. El script "test" del backend solo
          imprime un error, el frontend no tiene script de pruebas e index.js
          no exporta "app" (llama a listen directamente), lo que dificulta
          probarlo.

  [-] 15. En backend/middlewares/cors.js el dominio está mal escrito:
          "unibecas.orender.com" en vez de "onrender.com".

  [-] 16. El registro y el inicio de sesión son solo visuales: validan que los
          campos no estén vacíos, pero no envían nada. No existen rutas de
          usuarios ni autenticación en el backend. El rol de administrador en

  [-] 17. Puesta en marcha incompleta: el script SQL crea las tablas pero no
          trae datos, .env.template está vacío y el README no explica cómo
          ejecutar el proyecto.

  [-] 18. ESLint reporta errores en el frontend (por ejemplo, la variable
          "error" que no se usa en Header.jsx) y avisos de dependencias
          faltantes en useEffect.

// Pruebas unitarias: utilidades y esquemas Zod (sin base de datos)
import { describe, test } from 'node:test'
import assert from 'node:assert/strict'
import { validarIdEntero, horaActual } from '../utils/funciones/funciones.js'
import { validarBeca, actualizarBeca } from '../esquemas/esquemas.js'

const becaValida = {
    nombrebeca: 'Beca Talento Caribe',
    vigencia: '2026-12-31',
    descripcion: 'Beca para estudiantes destacados',
    aplicar: 'Presentar documento de identidad',
    modalidad: 'Pregrado',
    cobertura: '100%',
    iduniversidad: 1,
    estado: 'Activa',
    urlinfo: 'https://www.unicartagena.edu.co/',
    proveedor: 1
}

describe('validarIdEntero', () => {
    test('acepta un entero positivo en texto', () => {
        assert.equal(validarIdEntero('5'), 5)
    })

    test('rechaza cero, negativos, decimales y texto', () => {
        for (const valor of ['0', '-3', '1.5', 'abc', '']) {
            assert.equal(validarIdEntero(valor), false, `deberia rechazar "${valor}"`)
        }
    })

    test('rechaza valores mayores al limite de un integer de PostgreSQL', () => {
        assert.equal(validarIdEntero('2147483648'), false)
    })

    test('rechaza formatos que no son solo digitos (1e3, 0x10, espacios)', () => {
        for (const valor of ['1e3', '0x10', ' 7 ']) {
            assert.equal(validarIdEntero(valor), false, `deberia rechazar "${valor}"`)
        }
    })
})

describe('horaActual', () => {
    test('devuelve un texto no vacio', () => {
        assert.equal(typeof horaActual(), 'string')
        assert.ok(horaActual().length > 0)
    })
})

describe('validarBeca', () => {
    test('acepta una beca completa y valida', () => {
        assert.equal(validarBeca(becaValida).success, true)
    })

    test('rechaza un nombre compuesto solo por espacios', () => {
        assert.equal(validarBeca({ ...becaValida, nombrebeca: '   ' }).success, false)
    })

    test('rechaza una modalidad fuera del catalogo', () => {
        assert.equal(validarBeca({ ...becaValida, modalidad: 'Doctorado' }).success, false)
    })

    test('rechaza una URL invalida', () => {
        assert.equal(validarBeca({ ...becaValida, urlinfo: 'no-es-url' }).success, false)
    })

    test('rechaza iduniversidad enviado como texto', () => {
        assert.equal(validarBeca({ ...becaValida, iduniversidad: '1' }).success, false)
    })

    test('rechaza descripcion, requisitos y cobertura vacios', () => {
        for (const campo of ['descripcion', 'aplicar', 'cobertura']) {
            assert.equal(validarBeca({ ...becaValida, [campo]: '' }).success, false, `deberia rechazar ${campo} vacio`)
        }
    })

    test('acepta la modalidad "Tecnológica" con tilde que usa el frontend', () => {
        assert.equal(validarBeca({ ...becaValida, modalidad: 'Tecnológica' }).success, true)
    })
})

describe('actualizarBeca', () => {
    test('permite actualizar un solo campo', () => {
        const r = actualizarBeca({ estado: 'Vencida' })
        assert.equal(r.success, true)
        assert.deepEqual(r.data, { estado: 'Vencida' })
    })

    test('sigue validando el tipo de los campos enviados', () => {
        assert.equal(actualizarBeca({ estado: 'Cerrada' }).success, false)
    })
})

// Pruebas unitarias: modelo MainInfo (becas) con la base de datos simulada
import { describe, test, mock, beforeEach } from 'node:test'
import assert from 'node:assert/strict'

const consultas = []
let respuesta = { rows: [], rowCount: 0 }

mock.module(import.meta.resolve('../modelos/postgreSQL/conexion.js'), {
    namedExports: {
        pool: {
            query: async (sql, params) => {
                consultas.push({ sql, params })
                return respuesta
            }
        }
    }
})

const { MainInfo } = await import('../modelos/postgreSQL/main.js')
const { ErrorValidacion } = await import('../utils/errores/errorcharcount.js')

beforeEach(() => {
    consultas.length = 0
    respuesta = { rows: [], rowCount: 0 }
})

describe('MainInfo.allRecovery', () => {
    test('sin busqueda devuelve todas las filas', async () => {
        respuesta = { rows: [{ id: 1 }, { id: 2 }], rowCount: 2 }
        assert.deepEqual(await MainInfo.allRecovery({}), [{ id: 1 }, { id: 2 }])
        assert.equal(consultas.length, 1)
    })

    test('rechaza busquedas de menos de 4 caracteres sin consultar la BD', async () => {
        await assert.rejects(MainInfo.allRecovery({ schsp: 'abc' }), ErrorValidacion)
        assert.equal(consultas.length, 0)
    })

    test('envia la busqueda como parametro (sin SQL injection)', async () => {
        respuesta = { rows: [{ id: 7 }], rowCount: 1 }
        await MainInfo.allRecovery({ schsp: "medica'; DROP TABLE becas;--" })
        assert.equal(consultas[0].params[0], "%medica'; DROP TABLE becas;--%")
        assert.ok(!consultas[0].sql.includes('DROP TABLE'))
    })

    test('devuelve false si la busqueda no tiene resultados', async () => {
        assert.equal(await MainInfo.allRecovery({ schsp: 'inexistente' }), false)
    })

    test('escapa los comodines % y _ de la busqueda', async () => {
        respuesta = { rows: [{ id: 1 }], rowCount: 1 }
        await MainInfo.allRecovery({ schsp: '%%%%' })
        assert.notEqual(consultas[0].params[0], '%%%%%%', 'el texto "%%%%" no deberia comportarse como "traer todo"')
    })
})

describe('MainInfo.idRecovery', () => {
    test('con ID invalido devuelve false sin consultar la BD', async () => {
        assert.equal(await MainInfo.idRecovery({ id: 'abc' }), false)
        assert.equal(consultas.length, 0)
    })

    test('con ID valido devuelve la primera fila', async () => {
        respuesta = { rows: [{ id: 3, nombre: 'Beca' }], rowCount: 1 }
        assert.deepEqual(await MainInfo.idRecovery({ id: '3' }), { id: 3, nombre: 'Beca' })
        assert.deepEqual(consultas[0].params, [3])
    })
})

describe('MainInfo.newData', () => {
    test('lanza ErrorValidacion si los datos no cumplen el esquema', async () => {
        await assert.rejects(MainInfo.newData({ dataVal: { nombrebeca: 'Incompleta' } }), ErrorValidacion)
        assert.equal(consultas.length, 0)
    })
})

describe('MainInfo.deleteData', () => {
    test('devuelve false si no existe la beca', async () => {
        assert.equal(await MainInfo.deleteData({ id: '99' }), false)
    })

    test('devuelve true si la borra', async () => {
        respuesta = { rows: [{}], rowCount: 1 }
        assert.equal(await MainInfo.deleteData({ id: '1' }), true)
    })
})

describe('MainInfo.patchData', () => {
    test('no permite cambiar proveedor ni universidad', async () => {
        await assert.rejects(MainInfo.patchData({ id: '1', input: { proveedor: 2 } }), ErrorValidacion)
    })

    test('rechaza un cuerpo sin campos', async () => {
        await assert.rejects(MainInfo.patchData({ id: '1', input: {} }), /No hay campos/)
    })

    test('arma el UPDATE solo con los campos enviados', async () => {
        respuesta = { rows: [{ id: 5, estado: 'Activa' }], rowCount: 1 }
        await MainInfo.patchData({ id: '5', input: { estado: 'Activa' } })
        assert.match(consultas[0].sql, /SET estado = \$1/)
        assert.deepEqual(consultas[0].params, ['Activa', 5])
    })
})

##### backend/test/controlador-becas.test.js #####

// Pruebas unitarias: controlador MainControl con el modelo simulado
import { describe, test, mock, beforeEach } from 'node:test'
import assert from 'node:assert/strict'

const modelo = {}

mock.module(import.meta.resolve('../modelos/postgreSQL/main.js'), {
    namedExports: { MainInfo: modelo }
})

const { MainControl } = await import('../controladores/main.js')
const { ErrorValidacion } = await import('../utils/errores/errorcharcount.js')

function respuestaFalsa() {
    const res = { statusCode: null, body: null }
    res.status = (codigo) => { res.statusCode = codigo; return res }
    res.json = (cuerpo) => { res.body = cuerpo; return res }
    return res
}

beforeEach(() => {
    mock.method(console, 'log', () => { })
})

describe('MainControl.allRecoveryCont', () => {
    test('200 con la lista de becas', async () => {
        modelo.allRecovery = async () => [{ id: 1 }]
        const res = respuestaFalsa()
        await MainControl.allRecoveryCont({ query: {} }, res)
        assert.equal(res.statusCode, 200)
        assert.deepEqual(res.body, [{ id: 1 }])
    })

    test('404 si la busqueda no encuentra becas', async () => {
        modelo.allRecovery = async () => false
        const res = respuestaFalsa()
        await MainControl.allRecoveryCont({ query: { schsp: 'nada' } }, res)
        assert.equal(res.statusCode, 404)
        assert.match(res.body.error, /no encontrada/)
    })

    test('lista vacia: responde 200 con [] para que el frontend pueda recorrerla', async () => {
        modelo.allRecovery = async () => []
        const res = respuestaFalsa()
        await MainControl.allRecoveryCont({ query: {} }, res)
        assert.equal(res.statusCode, 200)
        assert.ok(Array.isArray(res.body), `respondio ${JSON.stringify(res.body)}`)
    })

    test('400 ante un error de validacion', async () => {
        modelo.allRecovery = async () => { throw new ErrorValidacion('corta') }
        const res = respuestaFalsa()
        await MainControl.allRecoveryCont({ query: { schsp: 'ab' }, params: {} }, res)

import { describe, test, expect, vi, afterEach } from "vitest";
import { render, screen, renderHook, act, cleanup, fireEvent, waitFor } from "@testing-library/react";
import { MemoryRouter, Routes, Route } from "react-router-dom";
import useFetch from "../hooks/useFetch";
import HomeLayout from "../home/layout/HomeLayout";
import Header from "../home/components/header/Header";
import BecaDetails from "../components/becaDetails/BecaDetails";
import BecaCard from "../components/becaCard/BecaCard";

const becaApi = {
  id: 7,
  nombre: "Beca Vocación Médica",
  vigencia: "2026-11-30",
  descripcion: "Beca orientada a jóvenes que desean estudiar Medicina",
  aplicar: "Presentar documento de identidad",
  modalidad: "Pregrado",
  universidad: "Universidad de Cartagena",
  cobertura: "70%",
  estado: "Activa",
  proveedor: "Universidad de Cartagena",
  url: "https://www.unicartagena.edu.co/",
};

function simularFetch(cuerpo, status = 200) {
  globalThis.fetch = vi.fn(async () => ({
    ok: status >= 200 && status < 300,
    status,
    json: async () => cuerpo,
  }));
}

afterEach(() => {
  cleanup();
  vi.restoreAllMocks();
});

describe("useFetch", () => {
  test("guarda los datos cuando la respuesta es correcta", async () => {
    simularFetch([becaApi]);
    const { result } = renderHook(() => useFetch());
    await act(() => result.current[3]("/main"));
    const [data, loading, error] = result.current;
    expect(data).toEqual([becaApi]);
    expect(loading).toBe(false);
    expect(error).toBe(null);
  });

  test("guarda el error cuando falla la red", async () => {
    vi.spyOn(console, "error").mockImplementation(() => {});
    globalThis.fetch = vi.fn(async () => {
      throw new TypeError("Failed to fetch");
    });
    const { result } = renderHook(() => useFetch());
    await act(() => result.current[3]("/main"));
    expect(result.current[2]).toBeInstanceOf(TypeError);
  });

  test("marca como error una respuesta HTTP 404", async () => {
    simularFetch({ error: "Not found" }, 404);
    const { result } = renderHook(() => useFetch());
    await act(() => result.current[3]("/main"));
    expect(result.current[2]).not.toBe(null);
  });
});
